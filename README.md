# 乐跑星球-校园跑球型机器人

基于 ESP32-S3 的两轮球型小车。

孩子们，大事不妙，我发现了屎山但是不是很想改，因为能用就不动了，在这里说一下情况。
首先根据编码器的脉冲计算转速，然后再根据转速和车轮半径计算线速度。电机最高转速是600转/分钟，轮子直径是66mm，因此最高速度是2.07m/s。而我给BLE传入的速度数值（±100）除以50归一化到±2，这样差不多最高速度就当作2m/s。
然后手机端里，用户操作的数据会归一化到±1，最高速度默认设置2.2m/s，转换后BLE传出的速度参数会变成±110，但是有硬编码上限，所以实际是±100。
这个逻辑本来没啥问题，但2代小车的车轮直径从66mm变成195mm，最高速度就从2.07m/s变成6.12m/s,那么问题来了。直接修改手机上的最高速度是没用的，因为输出会限制到±100。如果我直接修改小车的控制把BLE传入的速度数值（±100）归一化到±6，那么PID的参数就要大调，不然输出就会疯狂震荡。

归根结底小车的速度其实是转速，线速度是计算的数值，PID是根据线速度的数值来调的参。如果维持现状就完全没问题，不过线速度的显示就变成摆设了，还多了一次计算。

反正除了看串口，你们也不知道小车计算的速度，所以我就不改了，只把手机端的显示代码改改算了，azz
